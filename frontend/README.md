# MyPlayer — frontend

Чёрно-белый интерфейс в стилистике мрачной городской манги: тушь, штриховка, бумажная текстура и панельные рамки, без персонажей. Оригинальная SVG-иллюстрация ночного города. Интерфейс для FastAPI-бэкенда из `../backend`. Чистые HTML, CSS и JavaScript, без фреймворков и сборки. Мобильный ориентир — iPhone 15, **393 × 852 CSS px**; адаптивность от 320 px до десктопа.

## Запуск

1. Запустить бэкенд по [его инструкции](../backend/README.md), указав `AUTH_PASSWORD` и параметры нужных источников в серверном окружении.
2. Из корня репозитория запустить фронт на другом порту:

   ```sh
   python -m http.server 8081 --directory frontend
   ```

3. Открыть <http://localhost:8081>, указать адрес API (локально `http://localhost:8080`, в облаке URL сервиса Koyeb/Render) и пароль `AUTH_PASSWORD`.
4. Нажать «Обновить библиотеку», чтобы импортировать треки и плейлисты.

На iPhone открыть URL фронта с адресом компьютера в локальной сети, а в поле сервера указать доступный телефону адрес API — `localhost` на телефоне означает сам телефон. Для HTTPS-фронта нужен HTTPS-бэкенд. Для размещения на GitHub Pages достаточно опубликовать содержимое `frontend`; адрес API вводится при входе. Текущий CORS бэкенда разрешает отдельный домен фронта.

Пароль передаётся только в `POST /auth/login` и не сохраняется. JWT хранится в `sessionStorage`, отдельно для каждого адреса сервера; URL API — в `localStorage`. При 401 приложение сбрасывает воспроизведение и возвращает экран входа. «Выйти / сменить сервер» доступно через аватар или «Источники».

## Реальные функции

- `/status`: статус настройки VK, SoundCloud, Spotify и входа в Spotify.
- `/library/refresh`: синхронизация всех или выбранного источника. Ошибки отдельных сервисов показываются в «Источниках» и не блокируют остальную библиотеку. Автообновление — каждые 6 часов, пока вкладка открыта и видима.
- `/library/tracks`: поиск по импортированной библиотеке с задержкой 300 мс, отменой устаревших запросов, фильтром по источнику и пагинацией по 50 треков. Это не глобальный поиск в каталогах сервисов.
- `/library/playlists` и `/library/playlists/{source}/{external_id}/tracks`: реальные плейлисты и их состав.
- `/resolve`: получение аудиоссылки для выбранного `source` + `external_id`. Proxy-поток `/stream/<token>` открывается без JWT в `<audio>`, direct-ссылка используется напрямую.
- Пауза, очередь, следующий/предыдущий трек, перемотка, повтор, перемешивание, громкость и системные медиакнопки. Состояние плеера и время берутся из событий настоящего аудио. При ошибке потока выполняется одна повторная попытка через `/resolve`.
- `/auth/spotify/start`: вход в Spotify в отдельной вкладке; после завершения нужно вернуться и обновить библиотеку. В `SPOTIFY_REDIRECT_URI` на сервере и в настройках Spotify должен быть один и тот же адрес **`https://<адрес-api>/auth/spotify/callback`** (локально, например, `http://localhost:8080/auth/spotify/callback`).

Плейлисты источников только читаются. Свои плейлисты создаются в медиатеке и сохраняются в браузере отдельно для каждого API-сервера: можно добавлять/удалять треки, переименовывать и удалять плейлисты, скачивать резервную копию JSON. Они не синхронизируются между устройствами и не изменяют данные музыкальных сервисов. «Любимые треки», история и позиции синхронизируются через API сервера и не изменяют лайки в VK, SoundCloud или Spotify. Старое локальное избранное переносится идемпотентно; треки, которых пока нет на сервере, остаются в локальном списке для повторной попытки. Демонстрационных песен в библиотеке больше нет.

## Ограничения аудио

Safari на iPhone поддерживает нативный HLS. Если браузер не поддерживает HLS и сервер явно возвращает `.m3u8`, интерфейс предлагает открыть Safari или другой трек. Внешний HLS-плеер не подключён. Громкость на iPhone управляется аппаратными кнопками. При блокировке автозапуска браузером достаточно повторно нажать Play. Фронт запрашивает только полный звук (`full_only: true`). Если резолвер Spotify не находит полный трек, показывает ошибку; 30-секундные превью не используются.

Повторный `/resolve` не гарантирует свежую внешнюю ссылку: на бэкенде есть собственный TTL-кэш. Если провайдер уже отозвал закэшированный URL, понадобится его обновление на стороне сервера; фронт ограничивает повторы и показывает ошибку.

## Файлы

- `index.html` — каркас, SVG-иконки, навигация, плеер, диалоги.
- `styles.css` — тема, адаптивные экраны, safe areas и `prefers-reduced-motion`.
- `api.js` — HTTP-клиент, JWT, таймауты и обработка ошибок.
- `artwork.js` — ленивая загрузка обложек, поиск отсутствующих и замена недоступных картинок.
- `player.js` — очередь и настоящий `HTMLAudioElement`, Media Session.
- `app.js` — экраны, поиск, импорт, локальное избранное.
- `assets/` — иконки, запасные обложки и декоративное изображение.

Manrope загружается через Google Fonts, при отсутствии сети используется системный шрифт. Обложки треков приходят с сервера; если обложки нет или она не загрузилась, показывается локальная SVG. Декоративное изображение `night.jpg`: <https://images.unsplash.com/photo-1519608487953-e999c86e7455>. SVG нарисованы для интерфейса.

## Проверка

```sh
node --check frontend/api.js
node --check frontend/artwork.js
node --check frontend/player.js
node --check frontend/app.js
python -m unittest discover -s backend/tests -v
```

API-тесты используют временную SQLite и подменяют только внешние музыкальные сервисы: пароль/JWT, синхронизация и частичный сбой, поиск/дедупликация/фильтр, состав плейлиста, resolve, direct/proxy и Range. Дополнительно интерфейс проверен в Chromium с запущенным FastAPI и тестовым WAV: вход, поиск, пагинация, плейлист, настоящее аудио, retry, перемотка, локальное избранное и истечение сессии; проверены ширины 320–1440 px. Реальные аккаунты сервисов и устройство с iOS Safari в этом окружении не использовались.

В бэкенде исправлены три ошибки, обнаруженные при интеграции: неподдерживаемый контекст SQLite Cursor в синхронизации и ленивом импорте; выбор версии трека из другого источника при фильтрации; регулярное выражение `feat/ft`, обрезавшее обычные названия и объединявшее разные песни.

## Обложки треков

Оригинальные картинки VK, SoundCloud и Spotify отображаются в чёрно-белом виде в списке треков, плеере и окне текущего трека. Если обложки нет или её URL недоступен, фронт запрашивает защищённый JWT маршрут `GET /artwork?title=…&artist=…`. Сервер ищет совпадение в публичном каталоге iTunes по названию и исполнителю. Для такого поиска эти два поля отправляются Apple; токены музыкальных сервисов туда не передаются. Подписка и API-ключ не нужны. Альтернативная обложка может относиться к другому изданию того же трека.

Запросы идут только для картинок рядом с видимой областью, не более трёх одновременно. Совпадения кэшируются сервером на сутки, отсутствие совпадения — на час; размер кэша ограничен. Если картинку найти не удалось, остаётся рисованная пластинка. Ошибка поиска не блокирует воспроизведение. Для этой функции нужно обновить и фронтенд, и бэкенд; реальные аккаунты источников в автоматических проверках не использовались.

- API: https://myplayer-after-dark-api.onrender.com
- Render: https://dashboard.render.com/web/srv-dbksttl9fdbs73c8pe7g

На опубликованном фронте API Render выбран по умолчанию. Локальный запуск на порту 8081 продолжает использовать порт 8080. Адрес можно изменить на экране входа; сохранённый ранее адрес имеет приоритет. Пароль хранится в переменной `AUTH_PASSWORD` сервиса Render. Токены источников задаются только в Environment сервиса, затем нужно выполнить Save and deploy и обновить библиотеку.

Сервис использует бесплатный тариф Render: после простоя первый запрос может занимать около минуты. SQLite на временном диске очищается при пересоздании сервиса; импортированную библиотеку нужно обновить, а Spotify подключить заново либо заранее задать `SPOTIFY_REFRESH_TOKEN`.

## Рекомендации и свои плейлисты

На главной и в разделе «Для тебя» — карточки Daily Mix, миксов исполнителей и «Заново открыть». Они собираются из первых 200 треков выбранного источника в импортированной библиотеке; избранное и история сеанса влияют на порядок. Daily Mix меняется по дате UTC. Это локальный подбор по доступной библиотеке, без анализа звучания и внешнего каталога Spotify. Для пустой библиотеки показывается предложение подключить источник, без демонстрационных песен.

В медиатеке: «Создать плейлист». Кнопка «+» справа от любого трека открывает выбор плейлиста. В своём плейлисте через неё можно убрать трек. Микс можно сохранить как свой плейлист; список сохранится, когда рекомендации обновятся. Свои плейлисты хранятся только в этом браузере (до 100 плейлистов по 1000 треков), поэтому удаление данных браузера удалит их. В меню плейлиста доступно скачивание JSON-копии; импорт JSON пока не поддерживается.

## Мобильная прокрутка

На ширине до 767 px плеер и нижняя навигация находятся в одном непрозрачном фиксированном блоке. Прокручивается только `.app-shell`; корневая страница закреплена, чтобы инерционная прокрутка и rubber-band в Safari не разносили нижние панели. Нижняя безопасная область учитывается через `safe-area-inset-bottom`. При смене раздела прокрутка контейнера сбрасывается; на десктопе остаётся обычная прокрутка страницы.

## Новые API плеера

Фронт использует `/favorites`, `/favorites/toggle`, `/history`, `/plays`, `/positions`, `/lyrics` и обновлённый `/status`. Для миграции лайков `/favorites/toggle` принимает `favorite: true|false`, чтобы повторный запрос не отменял лайк. При паузе и смене трека сохраняются позиция и длительность предыдущего трека. Предзагрузка следующего трека ограничена текущим сервером/сеансом и отменяется при выходе. Тексты подсвечиваются и прокручиваются внутри своего окна.

Важно: текущее бесплатное размещение Render хранит SQLite во временной файловой системе. Серверное избранное, история, позиции и OAuth-сессия могут исчезнуть при пересоздании сервиса. Для надёжной синхронизации между устройствами нужен постоянный диск или постоянная БД; это развёртывание пока не менялось. Свои плейлисты по-прежнему хранятся на устройстве.
