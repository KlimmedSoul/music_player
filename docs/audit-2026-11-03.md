# Проверка аудита от 3 ноября 2026

Источник: [замечания к PR №1](https://github.com/KlimmedSoul/music_player/pull/1#issuecomment-6604201456). Исходный аудит выполнен по `c9e0b12`; ниже учтены исправления в актуальной ветке PR.

| Пункт | Результат |
|---|---|
| 1 — битый `app/spotify.py` | Неиспользуемый дубликат удалён. |
| 2–3 — блокировка event loop / YouTube URL | Spotify использует тот же экземпляр коннектора YouTube Music. Поиск и резолв выполняются в threadpool; используется общий fallback `requested_formats`. |
| 4 — SQLite | Инициализация и доступ к общей коннекции сериализованы RLock. Записи выполняются транзакционно; сетевые запросы вне блокировок. Исправлено также зависание первой записи `store_set`. |
| 5 — названия `Ft. Lauderdale` | `feat/ft` удаляются только после разделителя, а не с начала названия. |
| 6 — дедупликация | Неизвестная длительность имеет отдельный маркер; ISRC — первичный идентификатор при наличии. Upsert единый для синхронизации и плейлистов, обновляет существующий ключ и ссылки избранного. |
| 7 — очистка TTL | `resolve` удаляет просроченные URL и выданные stream-токены; добавлены индексы времени. |
| 8 — повторная аудиоссылка | После мержа PR №1 добавлен принудительный `refresh` при retry: старая ссылка удаляется из кэша, выполняется новый запрос провайдеру. HLS определяется также по `content_type`, включая URL без `.m3u8`. |
| 9 — размер VK-плейлиста | Количество исполнителей больше не используется как число треков. Точный размер сохраняется после загрузки состава. |
| 13 — пустые плейлисты | Отдельный флаг `tracks_loaded` отличает загруженное пустое содержимое от отсутствующего кэша; наличие одной строки плейлиста недостаточно. Миграция старой схемы сохраняет строки. |
| 14 — JWT | Без заданного секрета генерируется случайный ключ. Явный публичный старый ключ блокирует запуск, кроме `MYPLAYER_ALLOW_INSECURE_DEV=1`. Render продолжает использовать свой постоянный секрет. |
| 15 — пароль | UTF-8 `hmac.compare_digest`; не более 10 неуспешных попыток в минуту на адрес клиента, ограниченное хранилище счётчиков. |
| Redirect URI | Добавлен в `backend/render.yaml`; файл прошёл проверку по текущей официальной JSON Schema Render. |

Дополнительно исправлены конкурентные лайки, не-JSON ответы Lrclib, формат альбома yt-dlp, жизненный цикл YoutubeDL и очистка временного cookies-файла. SoundCloud корректно разворачивает JSON-ответ transcoding endpoint и поддерживает progressive; неполные описания формата не вызывают KeyError. Для stream-прокси заданы явные connect/read timeout 10/60 с и предел ответа 512 MiB. Раньше shared httpx-клиент уже задавал timeout 30 с, поэтому утверждение о полном отсутствии таймаута было неточным.

Доступ без JWT проверяется для всех приватных эндпоинтов. `/healthz`, `/auth/login`, OAuth callback и `/stream/{opaque-token}` по контракту публичны; у callback проверяется OAuth state, у stream — выданный токен.

Проверки: 41 Python-тест, 7 тестов JavaScript, браузерные сценарии плеера, плейлистов и мобильной панели. Музыкальные источники в тестах подменены; физический iPhone и реальные аккаунты не использовались.

Ограничения: SQLite бесплатного Render остаётся временной; изменение постоянного хранилища не входит в этот PR. Перенос авторизации SoundCloud из query в OAuth-заголовок отложен согласно аудиту до проверки с реальным аккаунтом.
